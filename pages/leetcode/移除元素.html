问题如何逐步收敛？

宏观目标

未处理信息 → 0

消除所有尚未决策的元素，直到所有信息质点都完成分类。

微观指标

Φ = n - fast

用来衡量剩余的工作量。每处理一个元素，未决策工作量就减少 1。

状态势能观察

Φ → 0

指标下降条件：fast = fast + 1
因此 Φ 逐步收敛

终止条件：fast = n
此时 Φ = 0

07信息空间划分
SPACE PARTITIONING
HOW DO WE DIVIDE THE SPACE?

处理过程中形成哪些区域？

空间三分（Partitioning）

动态切分中
已保留 [0, slow)
已排除 [slow, fast)
未处理 [fast, n)
■ 有效结果区（保留）
■ 已处理废弃区
■ 未处理区域
■ 逻辑边界（指针）

区域职责

[0, slow)：已确认保留的有效元素。
[slow, fast)：已处理，但不属于有效结果的废弃区。
[fast, n)：尚未处理的元素。

边界的职责

slow 是有效结果区的右侧边界。
fast 是未处理区的左侧边界。
这两个逻辑边界共同维护了数组的处理状态。

空间划分是为了明确不同区域的职责
三区域 保留·废弃·未处理

如何实现这套处理流程？

Solution.java
class Solution {
    public int removeElement(int[] nums, int val) {
        int slow = 0;

        for (int fast = 0; fast < nums.length; fast++) {
            if (nums[fast] != val) {
                nums[slow] = nums[fast];
                slow++;
            }
        }

        return slow;
    }
}

13正确性与复杂度验证
CORRECTNESS
WHY DOES IT WORK?

如何证明算法一定正确？

不变量 A · 保留区

每轮开始时，nums[0:slow] 中的所有元素都不等于 val，且保持原有相对顺序。

不变量 B · 未处理区

每轮开始时，nums[fast:n] 中的元素尚未被本算法检查，等待逐个切分归属。

三个时刻验证

INITIAL
初始化

slow = 0，保留区为空，天然满足不变量。

MAINTAIN
维持

相等则划入废弃区；不等则写入保留区末尾。

TERMINATE
终止

fast = n，所有空间都已切分完毕。

CONCLUDE
结论

前 slow 个元素全部满足条件，返回 slow。

时间复杂度

fast 指针只向右移动，最多遍历数组一次，所以操作次数为 O(n)。

空间复杂度

算法只在原数组上直接进行覆盖操作，没有分配额外的数组，因此为 O(1)。

正确性来自不变量；性能来自对空间的原地复用
